# AgentDojo 诊断、修改与复测计划

更新：2026-11-20。阶段：中期答辩已完成，准备最终答辩。第三条工作线由本次计划提出者负责。本文是当前实施计划，历史六周方案及中期结果保留原始口径。

## 目标与判断

路线可行：从逐题证据建立失败分类，找到宿主适配、策略、恢复和评分之间的具体责任点，再用最小改动与配对实验验证。先不预设“问题必定在核心修复算法”，也不以放宽所有权限来换取任务成功率。验收同时考察正常效用、攻击目标达成和修复后的恢复能力。

AgentDojo 用于工具代理诊断；这条线的结果不能替代 RedTeamCUA 的 GUI 验收或 ChatGPT Desktop 的接入验收，也不能单凭规划前重跑证明长时记忆恢复。

## 代码来源与优先假设

| 优先项 | 代码位置与已有事实 | 待验证机制与修订方向 |
|---|---|---|
| P0 精确参考轨迹授权 | `scripts/agentdojo_midterm.py:initial` 从 `task.ground_truth()` 取写操作；`Pipeline.query` 对工具名与完整参数 JSON 精确匹配后才发 HostGrant | 这是本项目评测适配的授权构造，不是 AgentDojo 官方评分规则。合法替代表述、不同工具路径或动态 ID 可能缺少授权；用人工审核的任务约束与候选授权规则对照，移除答案依赖 |
| P0 策略版本漂移 | 历史结果发布于 `948ea6c`；后续 `b8812b4` 的 `label_policy.check_action` 对 `send_email` 强制确认和可信证据；当前入口构造 HostGrant 时不提供 confirmation_id | 先复现当前失败，明确宿主如何从可信用户任务生成范围有限的授权，禁止把模型自述确认或参考答案当作用户确认 |
| P1 证据绑定过宽 | `Pipeline.query` 将此前全部观察加入 evidence；`label_store.ingest` 的 tool 通道为 UNTRUSTED | 当前策略下，无关旧观察可能参与高风险判断。研究参数级证据和授权证据分离；须保留真正的数据依赖，不能简单丢弃所有不可信证据 |
| P1 修复与门控混杂 | `agentdojo_midterm_inspect.py:evaluate` 用已知干净值 rebuild，再创建新 Pipeline + 同一 gate 策略运行 | 目前测的是干净备份恢复后的规划前重跑；需增加无修复干净对照及相同检查点恢复对照，区分 gate、状态修复与任务规划问题 |
| P1 可观测性与预算 | 8 轮工具选择、16,000 字符观察截断、前缀式 is_read、拒绝消息较笼统 | 按工具 schema 审核动作分类；记录截断、异常、预算终止和拒绝后的重复尝试。各组保持相同预算，不用单独加预算掩盖防御损失 |

精确绑定“已批准动作”仍是必要的执行检查；需改进的是批准范围如何由任务权限生成，而不是删除执行时的参数绑定。以上是静态证据与候选因果机制；尚未确认上游 SRR、TMA 或 LangGraph 存在缺陷，不能把本地适配问题归咎于上游。

## 统一指标与失败分类

正常效用报告 `通过/计划任务数`，另列可评分覆盖率；攻击报告官方目标达成、受攻击任务效用、注入暴露情况。未知/错误不得当作安全成功。旧 goal_text_observed 只检查完整目标字符串，不足以证明实际暴露与否。

误拦截必须经案例审核：动作在用户授权和任务约束内，却被防御拒绝。分别报告“含任意拒绝的任务比例”“确认误拦截的任务比例”和“误拒绝调用/审核合法调用”，标明分母，不能互换。

恢复报告状态校验通过率、校验通过后的条件续行成功率、全部指定恢复案例的端到端成功率、正常信息保留和复发率。分别记录检测、修复、续行成本；历史总 tokens 无法可靠拆分时保持缺失。

失败先按可观测事实分类：基础模型/工具失败、授权范围不匹配、证据或版本拒绝、错误恢复状态、恢复后上下文缺失、轮数/截断限制、API/环境异常、评分差异、原因不明。允许多因并存；只有相同案例的受控反事实改动能够支持因果归因。
