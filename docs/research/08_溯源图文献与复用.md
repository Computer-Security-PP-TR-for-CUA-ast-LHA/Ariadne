## 本地实现了什么

新增 `src/cua_guard/provenance/` 完整溯源图子系统：

1. `GraphNode` 覆盖 `user_input / step / memory` 三种节点，并由 step type 给出细粒度语义类型。
2. builder 根据宿主捕获的 session、trace step 和 memory record 自动分配 turn，并构造 `chain/produce/support/delete/update/consolidate/initiate/derive/supersede/cite` 十类边。
3. `DependencyGraph` 为同一节点对保存多标签，维护正反向索引，并提供确定性 JSON 往返。
4. 查询层支持类型化祖先/后代、多污染根闭包、受影响诱导子图、producer 和拓扑查询；污染传播排除纯 `chain`。
5. 校验层检查覆盖状态、端点、双向索引、turn、producer、lineage 和环；JSON/SVG 导出不需要额外绘图库。
6. `recovery.adapters.snapshot_from_provenance()` 仅投影 memory 与 `derive/supersede`，保持现有 `ariadne.recovery/0.2` 数据库和修复接口兼容。
7. `recovery.dgrr.DGRRReachability` 改为本地兼容层，默认被 `VersionGraph` / `RecoveryCoordinator` 使用。

验证入口（**不需要** memory-rollback checkout）：

```powershell
$env:PYTHONPATH = 'src'
python -m unittest tests.test_provenance_graph -v
python -m unittest tests.test_recovery -v
```

可选：恢复 demo / SRR writer 重放仍可能需要外部 SRR 目录，那是恢复链路的事，与溯源图建图无关：

```powershell
# 仅当要跑 SRR 原始 writer 对照时才需要；溯源图本身不读这个变量
$env:ARIADNE_SRR_CHECKOUT = '<外部目录>\selective-revocation-replay'
python -m cua_guard.recovery.demo
```

## 许可与表述边界

- `memory-rollback` 没有可确认的项目级许可证。公开可读不等于允许复制或再分发，因此本仓库不保存、不运行其实现。
- 当前代码应准确表述为“参考论文方法的独立实现”，不能表述为“调用作者原代码”或“完整复现论文系统”。
- 本地实现覆盖论文图子系统的三类节点、十类边、trace 建图、校验、查询及导出；论文的 fault provenance、stale-window、support checker、rollback optimizer、修复执行和完整 benchmark 流程不属于本模块。
- 真实 CUA 宿主自动 hook 尚未接入；当前通过 `ProvenanceRecorder` 或测试/fixture 喂结构化记录。
- 论文图可用于课堂展示时仍应按学校和出版方规则引用；仓库文档不直接复制论文图片，以避免将学术引用误当成图片再发布许可。
