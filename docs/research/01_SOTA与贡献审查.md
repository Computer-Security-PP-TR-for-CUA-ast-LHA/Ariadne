# SOTA 与贡献审查

核查日期：2026-10-14。本文为定向调研，不是系统综述；没有独立复现所引论文，也未证明全领域不存在相同方案。论文作者的实验结果不等于我们验证的结果。

## 1. Proposal 实际承诺

修订版第 4 页提出：外置插件维护“内容 ID + 版本 + 来源/权限/状态”；在输入、摘要、记忆、执行链上记录派生关系；按告警调用 ID 查询溯源图；修复污染节点及副本，保留正常状态并复检。第 5 页计划在 RedTeamCUA 和 AgentLAB 上比较 B0 原始、B1 标签、B2 修复、B3 全方案，评估安全、恢复、成本及移植性。

这一定义同时包含来源一致性、授权、安全告警、污染定位、状态修复和任务续行。它们需要分别验证，不能用一个“ASR 下降”替代全部贡献。

## 2. 最接近工作的覆盖范围

| 工作 | 本轮核对范围与已覆盖主题 | 对本项目的约束 |
|---|---|---|
| [MemLineage](https://arxiv.org/html/2605.14421v1)，2026-05 预印本 | 正文设计、评估和讨论：签名来源、派生 DAG、持久标签、敏感动作门控；还评估参数级 authority repair | 与 Proposal 最直接重叠。“标签 + 图 + gate + 修复”不可整体称首次；需比较持久副本撤销与任务续行，且不能假定对方没有恢复机制 |
| [PPMF](https://arxiv.org/abs/2607.29167)，2026-07，页面标注 submitted | 摘要核验：宿主来源随记忆整合保持，按动作风险匹配来源权威 | 双份标签和摘要不增权属于已有思路。全文和公开代码仍需补核 |
| [TMA-NM](https://arxiv.org/html/2606.24322v1)，2026-06 预印本 | 正文机制与假设：写入时来源绑定、变换不增权、独立确认/动作绑定授权；依赖可信 origin oracle | 不可宣称首次不可洗白授权。其定理受模型和可信边界约束，不能推广到任意桌面；也不能把文中代理 baseline 当原方法完整实现 |
| [CausalArmor](https://arxiv.org/html/2602.07918v1)，2026-02 预印本 | 正文：决策点 LOO 归因、选择性净化，采用操作性因果影响定义 | 普通读写图不是 causal graph；需要干预证据。黑盒 CUA 无法直接访问所有 logits/内部推理，不能无条件照搬实现 |
| [MemSecBench](https://arxiv.org/html/2607.27080v1)，2026-07 预印本 | 正文 Write–Execute–Forget 协议及附录修复判定 | 已有选择性修复和正常记忆保留。文中也区分“语义仍在”与“能检索并完成后续任务”，后者可作为我们明确测量的扩展 |
| [ChronoMem](https://arxiv.org/html/2607.27773v1)，2026-07 预印本 | 摘要及局限：全量记忆快照、自然语言版本定位、全局回滚；当前线性历史 | 必须加全量回滚 baseline；不能声称首次版本化恢复。局部依赖闭包与保留后续正常更新是候选差异 |
| [MemForm](https://arxiv.org/html/2610.14431v1)，2026-10-10 预印本 | 摘要和方法框架：内容、证据、范围、选择、整合路径五种形成接口 | 图中只有保留下来的内容还不够；选择与顺序也可能影响结果。加入顺序与保留策略扰动，避免将内容 lineage 误当全部影响 |
| [eTAMP](https://arxiv.org/abs/2604.02623)，v2 2026-04-07 | 摘要核验：通过环境观察形成跨会话、跨站点记忆污染 | 跨会话与纯环境入口已不是空白；攻击是否真正由受害者写入必须单独验证 |
| [PMPA](https://arxiv.org/html/2609.13889v1)，2026-09 预印本 | 摘要及实验设置：外部来源诱导 harness 写入持久记忆，后续触发 | “外部文档到记忆再到动作”不能当新攻击；应作为威胁与攻击实现参考 |
| [AgentLAB](https://arxiv.org/abs/2602.16901)，2026-02 预印本 | 摘要与官方仓库：多轮自适应攻击、工具环境与记忆污染 | 使用其长时程设置需固定攻击预算；工具型实验不能直接称真实 GUI 实验 |
| [RedTeamCUA](https://github.com/OSU-NLP-Group/RedTeamCUA)，仓库标注 ICLR 2026 Oral | 官方 README：混合 Web–OS 环境、VM 与网页服务部署 | 适合 GUI 迁移验证，但基础部署重；新增跨会话协议要与原 benchmark grade 分开报告 |
| [CaMeL](https://arxiv.org/abs/2503.18813)，2025 | 摘要核验：结构性隔离控制流/数据流、能力约束 | 明确继承信息流和能力约束思想；没有忠实复现时称 policy/IFC-inspired baseline |

## 3. 原 novelty 逐项审计

| 表述 | 结论 | 改写 |
|---|---|---|
| 一式两份维护来源标签 | 工程冗余，不是独立安全贡献；两份都由 agent 控制则无可信增益 | 宿主账本为权威，内联 envelope 为引用；验证丢失、错配、版本漂移 |
| 面向修复构建溯源图 | 已有 lineage、撤销/恢复相关方法，不能泛化称新 | 版本级依赖闭包用于失效传播，并提供缺边/过度传播下的恢复权衡证据 |
| 精准清理污染与派生副本 | 目前只是假设；混合摘要难以逐句准确归因 | 初始保守隔离，随后从干净输入重建并独立验证；量化误伤与复发 |
| Causal Attack Graph | 观测依赖不自动产生因果结论 | 当前称 provenance/dependency graph，干预支持边另行标记 |
| 普遍适配 CUA | 当前无法成立；纯截图、闭源记忆可能无 hook | 优先一个可插桩 harness，再迁移第二个；公布支持矩阵与未覆盖路径 |
| 防护更有效 | 无实验支持 | 预注册安全—效用—恢复成本对照，允许零收益或负结果 |

## 4. 推荐贡献候选与反证条件

**C1：面向跨会话持久副本的版本撤销与重建协议。** 记录根、摘要、记忆、文件的版本依赖；告警后隔离受影响闭包，保持独立更新，从干净输入生成新版本。新增点必须表现为相较 gate-only、参数修复或全局回滚更好的后续任务恢复，而不是多了一张图。若完整图依赖 oracle 才能构建，或内容级混合导致几乎全部状态被隔离，贡献显著减弱。

**C2：恢复完整性的受控评估协议。** 同时检查旧版本不可检索、缓存/上下文无残留、正常任务续行、未来触发不复发。保持未改造 benchmark 的原 grade；扩展任务单独命名。若只测删除命令成功或 memory snapshot 无恶意字符串，证据不足。该协议须与 MemSecBench、ChronoMem 的实际实现逐项比对后再判断是否新颖。

**C3：不完整来源下的安全与恢复权衡。** 控制缺边率、压缩深度、混合正常信息比例和 detector 定位错误，报告对漏修、误隔离、恢复开销的影响。若缺边完全由实验脚本任意造出、没有真实 adapter 的缺失类型支持，只能算合成消融。

这些候选是我们对已核实文献的推论，不是论文作者给出的结论，也不是“无人研究”的证明。课程目标可表述为复现、实现与受控扩展；RAID/ACSAC 仅作为条件性后续方向。

## 5. Go / no-go 判断

- **继续：** 四人课程项目可以完成小型原型、一个工具型接入、少量 GUI 验证及诚实的实验分析。
- **先做两周 pilot：** 无防护确实发生污染与危害；固定同一 detector，图修复相对强恢复 baseline 有收益；新增正常更新被保留。
- **收缩：** 若图仅重复捕获所有上下文，改为 chunk/字段级边；若精确采集不可行，研究 conservative quarantine 的成本，不承诺精准修复。
- **停止论文级扩张：** 两周内无法证明区别于 MemLineage/ChronoMem 的恢复收益，或真实执行路径无法强制经过 gate，则转为复现与局限分析。无需为维护开题表述而挑选容易攻击的弱 baseline。
